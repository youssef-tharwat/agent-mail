# Agent Mail v0.7.0

Independent fleets, durable agent registration and truthful delivery diagnostics.

## Install

```sh
brew update
brew upgrade youssef-tharwat/tap/agent-mail
```

Prebuilt macOS/Linux binaries support ARM64 and x86-64. No Rust compiler required.
Herdr remains optional: `herdr plugin install youssef-tharwat/agent-mail`.

## Changes

- Agent registrations have typed registered/retired states, versions, reasons and
  bounded history. New `agent show`, `agent update` and `agent history` commands.
- Retirement rejects open owned/written tasks and pending incoming/outgoing mail.
  Restoration rotates standalone credentials and invalidates runtime attachments;
  exact retries are idempotent and explicit delivery pause is preserved.
- Groups can be added while the service runs on the current schema.
- `status` respects group selection; `status --all-groups` explicitly shows the
  installation overview. Bounded diagnostics filter by group before truncating.
- Status and database errors identify the selected store. Herdr binding rejects
  disabled plugins, and diagnostics check enablement and prompt policy separately.
- The bundled skill teaches fleet isolation, registration lifecycle and delivery checks.

## Upgrade

Schema 15 needs a one-time migration. Stop the service and clients, back up the
state directory, run `agent-mail init YOUR_EXISTING_GROUP`, then restart them.
Existing registrations import as registered/version 1 with an import history entry.
Older binaries cannot open the upgraded store; upgrade relay peers together.
Adding further groups does not require a service stop after migration.

With multiple groups, use `--group GROUP` or an authenticated group identity.
Installation-wide status now requires `--all-groups`. Cross-group messaging is
not included. Herdr prompt delivery remains notification-only unless an operator
explicitly chooses the unguarded prompt policy; the API cannot check for drafts.

## Verification

Local validation passed 85 tests, strict Clippy, formatting and both CLI flows.

Regression coverage includes a populated schema-14 upgrade, stale credentials,
retry conflicts, retirement races, overlapping agent/task names across groups,
a fleet larger than diagnostic limits, and disabled-plugin diagnostics.
Isolated CLI acceptance covers a running service enrolling a second fleet while
preserving pending mail, plus assignment through review, acceptance and replies.
Release CI runs tests and strict Clippy on all four binary targets.
