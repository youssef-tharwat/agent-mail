## Agent Mail v0.5.1

Register an agent, then launch it. No credential copying or shell exports.

```sh
brew update
brew upgrade youssef-tharwat/tap/agent-mail
npx skills add youssef-tharwat/agent-mail --skill agent-mail -g

agent-mail init project
agent-mail agent add worker
agent-mail run worker -- claude
# Or: agent-mail run worker -- codex
```

The agent skill is required. New installations use `brew install` instead of
`brew upgrade`. Prebuilt binaries support macOS 14+ and Linux glibc 2.35+, ARM64
and x86-64, without Cargo.

### Changes

- `participant` is now `agent`, with no compatibility alias.
- `run NAME -- COMMAND` supplies private, process-scoped identity automatically.
- Claude and Codex launches receive Mail recovery hooks. Native hook trust and
  permissions remain enforced; review Codex hooks when prompted.
- Claude uses an additive hook plugin, preserving user settings and custom hooks.
- Codex uses `--no-daemon` to keep each launch’s identity out of a shared process.
- Normal registration no longer prints credentials. `--show-session` is available
  explicitly for manual integrations.
- Native terminal behavior, child exit status, signals and resume arguments remain intact.

### Upgrade

Existing schema 12 databases need no migration. Update scripts from `participant`
to `agent`, update the required skill, and use `run` for standalone launches.
Remove older manually installed Mail hooks before adopting `run` to avoid
running duplicate hooks. Herdr pane-bound agents continue using verified Herdr
identity and must be launched by Herdr. The Mail delivery service remains separate;
Codex idle wake still requires an attached app-server endpoint.

[User guide](https://github.com/youssef-tharwat/agent-mail/blob/v0.5.1/docs/usage.md)

The v0.5.0 candidate was not published: its Linux release gate exposed a brittle
five-second limit around 100 durable writes. The stream test now distinguishes
reconciliation from write liveness, reports committed progress on timeout, and
allows shared CI storage latency. Runtime stream behavior is unchanged.
