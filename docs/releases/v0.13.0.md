# Agent Mail v0.13.0

Every new message requires typed context: a task and the version the sender
observed, or an explicit conversation. Replies inherit their parent's exact
context. Context identifies the work or discussion; communication intent still
determines whether an answer is owed, and task writers retain decision authority.

Task mail uses `--task ID --version VERSION`. Start a discussion with
`--new-conversation`, continue it with `--conversation UUID`, or inherit a visible
parent with `--reply-to MESSAGE_ID`. A send returns its concrete context, and an
identical retry retains the same message and conversation. Older task observations
remain visible; unknown and future task versions are rejected before publication.

`mail conversation UUID` provides bounded, paginated summaries of messages the
caller authored or received. Membership never grants access to other recipients'
messages. History reads do not acknowledge delivery or complete work. Interim
reply sends leave their original requests pending; final replies preserve atomic
response and resolution. Portable parent UUIDs survive delivery to a recipient
whose store does not contain the private parent.

Schema 26 adds immutable context and reply ancestry. The verified upgrade recovers
conversation roots from historical mail and queued relay traffic without inventing
observed task versions. Existing task links, message contents, canonical retry
records, dispositions, registrations, receipts and attempt budgets are preserved.
The guide refreshes once on each client's next input hook.

This is a breaking CLI, library publication and relay change. New sends cannot
omit context. Relay hops must advertise `mail_context_v1`; synchronize upgraded
peers before new mail is sent. Contextual events are a distinct wire variant, so
older peers reject them instead of silently dropping context. Legacy queued mail
is converted once during migration; new unscoped publications and old mail event
variants have no runtime fallback.

Regressions cover context validation, task observations and reply inheritance,
private threads, paging, concurrent retries, restart, durable database constraints,
historical migration, relay negotiation, forged revisions and changed contexts,
and private parents absent from a recipient's store.
