# Agent Mail v0.15.0

Task results now create a durable obligation for the current decision writer.
The owner submits `task report TASK --file result.json` with the observed task
version, a stable retry key, summary, source revision, evidence and explanation.
One transaction saves immutable evidence and publishes a mandatory request;
delivery, retrieval and task acceptance remain separate. Identical retries return
the original result, and conflicting retries fail. Results cannot be quiet notices
or withdrawn by their owner. The writer inspects `task result ID` and applies an
authorized decision with `task update ... --resolve MESSAGE_ID`.

Pending results hold owner reminders for the current assignment while preserving
the original supervision deadline. Writer transfer forwards the pending request
atomically, preserves reporter identity for replies and waits, and grants the
successor access to the typed result. Ordinary private mail retains its existing
inbox and dispositions. An already-published task escalation receives fresh
successor attention, including when authority returns to a previous writer,
without resetting its deadline, history or operator notification budget.

Herdr delivery consent now belongs to an exact session endpoint, including the
socket, pane, terminal, agent kind and native session identity. Explicitly bound
addresses for that same endpoint share consent across groups; permissions,
mailboxes, receipts, group pauses and binding opt-outs stay separate. Another pane
or replacement session receives no inherited consent. Configure a verified target
with `runtime herdr-policy unguarded --agent NAME`, or configure the authenticated
calling session without `--agent`.

`attention session` provides a bounded, paginated view of the current session's
registered groups without recording receipts. Recovery identifies additional
bindings. Wakes include the exact group fetch command; eligible attention is
selected fairly across shared endpoints, and an unread lease in one group cannot
block another group's eligible notification. Prompt-budget limits defer a delivery
challenge without losing the actionable hint or spending an unsent attempt.

Schema 28 preserves business state and transport receipts. Legacy conflicting
group consent choices migrate conservatively to notification-only, existing
matching endpoints retain unanimous consent, and future sessions do not inherit
group defaults. Existing native launches receive the updated operating guide once.
Result submission currently requires the task's authoritative local store; remote
snapshot holders continue to use contextual mail.

The release also fixes concurrent receipt-bearing result reads, shares the
128-byte revision bound with acceptance and prerequisites, validates pagination
cursors, reports delivery-preference inspection errors explicitly, and reconciles
writer-transfer and binding-control documentation. Local verification passed
251 tests, Clippy with warnings denied, formatting and whitespace checks; two
independent review contexts converged with no remaining findings.
