# Agent Mail v0.12.1

Launching a command through an existing identity now reads that identity without
attempting another registration insert. Read-only commands launched with
`run NAME -- ...` can proceed while an unrelated writer holds the database lock.
First-time registration remains atomic, and retired or runtime-owned identities
remain rejected.

This fixes unnecessary write contention observed during the v0.12.0 live rollout.
A regression holds a separate database write transaction while launching an
existing identity's version command. It reproduced `database is locked` before
the fix and succeeds afterward without changing the registration generation.
The full suite, strict Clippy, formatting, and native release checks run on
macOS and Linux, ARM64 and x86-64.

The attention, intent, waiting, and exact-receipt behavior introduced in
[v0.12.0](https://github.com/youssef-tharwat/agent-mail/releases/tag/v0.12.0)
is unchanged. Existing installations remain on schema 24;
opening state replaces the owned worker with this version and preserves delivery
budgets, registrations, obligations, and saved group policies.

Upgrade through Homebrew or the published installer/native archive.
