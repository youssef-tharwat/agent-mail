# Agent Mail v0.14.4

Delivery verification now coalesces with notifications that are eligible to send
now, using the same selection rules as normal delivery. Retained wake records
for retrieved events, outdated follow-up occurrences, or exhausted and cooling
notification budgets no longer prevent an idle agent from receiving its check.
Eligible work still carries the check in one prompt.

Together with v0.14.3, this repairs checks that previously expired without a
single attempt while agents were busy, then remained blocked by historical wake
records. The 180-second acknowledgment window starts with the first dispatch;
waiting consumes no attempt. Dispatched checks retain the three-attempt limit,
current identity and route validation, and explicit recipient acknowledgment.
No notification budget, mail obligation, or task state is reset. Schema remains 27.

Regression tests cover retrieved and exhausted wakes, unchanged pending mail and
notification budgets, and coalescing with eligible work after a long busy wait.
