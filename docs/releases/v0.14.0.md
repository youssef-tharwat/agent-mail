# Agent Mail v0.14.0

Subtasks are normal tasks with independent owners, writers, revisions and
acceptance decisions. Create one with `task create CHILD "SCOPE" --owner OWNER
--parent PARENT --parent-version VERSION`. Creation and the parent link commit
atomically; identical retries retain the original result. `task tree PARENT`
shows a bounded graph. Material child progress prompts the parent writer to
inspect the child, without accepting or reopening the parent.

Each task has one persistent, writer-owned dependency plan. Replace it with
`task dependencies ID --file plan.json`; inspect it with `task dependencies ID`.
The complete update checks the source and every prerequisite's observed version,
advances the source once, and records the decision through the normal audit and
relay path. A plan contains an `all` or `any` rule and up to 32 distinct conditions,
each selecting qualifying lifecycle states and an optional exact accepted
revision. Empty requirements clear the plan. Cancellation qualifies only when
explicitly selected.

Dependency edges and readiness are database projections of the plan, shared by
inspection, cycle checks and scheduling. Plans survive source updates and restart.
Unmet conditions suppress owner follow-up reminders while preserving the original
hard supervision deadline. Ready conditions prompt reassessment; review and
blocked holds retain writer authority. Reopening a prerequisite invalidates queued
readiness in the same transaction and allows a new readiness notification when
the contract qualifies again. Operator escalation history and retry budgets remain
attached to the overdue obligation.

Parent links organize work without implying prerequisites. Declare a dependency
when a parent's next action needs a child's outcome. Checkpoints remain temporary
progress reports that can add a wait; they cannot bypass a writer's persistent
contract. Mail continues to use the specific task and observed revision.

Schema 27 converts former active dependency links into explicit plans with
`done`/`accepted` outcomes. Historical link facts remain available as inactive
records. Queued and cached graph snapshots are converted from their own historical
facts, preserving envelope identities, task states, versions, deadlines, mail,
receipts and attempt history. More than 32 distinct legacy prerequisites aborts
the verified upgrade rather than silently truncating requirements.

This changes the graph mutation and relay contract. Generic `task relate` no
longer creates dependency links; use the complete dependency-plan command.
`task_graph_snapshot` is a distinct relay event, and peers must advertise
`task_graph_v1`. Older peers reject the event rather than dropping conditions.
Remote inspection exposes cached plans with unknown readiness; scheduling and
subtask-tree inspection remain on the group's home machine.

Regression coverage includes atomic child creation, independent authority,
parent reassessment, explicit outcomes and revisions, all/any combination,
cycle checks across plans and checkpoint waits, changed retries, restart, stale
delivery claims, readiness rearming, preserved escalation boundaries, historical
migration, and relay capability negotiation and validation.
