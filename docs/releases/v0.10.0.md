# Agent Mail v0.10.0

Agent Mail now tracks follow-through after a notification is delivered or read.
Unfinished work can carry a durable next step or explicit waiting condition;
bounded reminders and escalation keep abandoned decisions visible across restarts.

## Changes

- Add versioned task/mail checkpoints, explicit dependency and approval waits,
  checkpoint history, and recipient-scoped attention commands.
- Reconcile due work in the delivery service. Preserve escalation boundaries,
  idempotency, writer authority, and existing transport retry limits.
- Escalate to the task writer or request sender, then to an independent operator
  route. Failed operator alerts have bounded retries and visible diagnostics.
- Wake manually launched Herdr idle/done clients when optional launch metadata
  is absent. Explicit unready, blocked, and active states still prevent prompting.
- Keep retrieval and handling instructions in compact notification payloads.
- Separate transport verification, record retrieval, reported progress, and
  completion in status and recovery. Paginated status retains complete totals.
- Automatically coordinate schema upgrades, verified backups, worker handoff,
  and resumable watches using the current binary.

## Upgrade and activation

Update with `brew upgrade youssef-tharwat/tap/agent-mail`, or use the release archive
for your platform. Schema 18 preserves existing tasks, messages, registrations,
receipts, retry budgets, and pause settings. Existing stores migrate on normal use;
read-only diagnostics do not perform migration.

Follow-through starts in **observation mode**. Enable a group's follow-up dispatch
explicitly using `attention configure --file policy.json`. See the
[activation and checkpoint guide](../usage.md#follow-through-after-delivery).
Disabling dispatch preserves its records and history.

Event subscriptions use protocol 2. Upgrade old watch clients when they receive
the explicit protocol error. Remote snapshots and cross-machine waits remain
unsupported for follow-through; ordinary relay contracts are unchanged.

## Validation

The local macOS suite passes 137 tests, including 19 follow-through cases, plus
formatting and strict Clippy. Release builds repeat these checks on macOS and Linux
for both ARM64 and x86-64. Live acceptance evidence is recorded in
[FOLLOW_THROUGH_ACCEPTANCE.md](../FOLLOW_THROUGH_ACCEPTANCE.md).
