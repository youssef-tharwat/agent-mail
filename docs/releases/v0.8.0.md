# Agent Mail v0.8.0

- First `run` creates a missing registration and native launches establish the local
  worker. Existing identities, retired registrations and runtime ownership are preserved.
- Delivery readiness requires an exact agent acknowledgment plus current endpoint
  health. Runtime receipt alone cannot mark a client ready. Checks are durable,
  bounded and scoped to the current identity, launch and endpoint.
- A pending task/mail wake carries the check in the same delivery. Agents with no
  pending wake receive a standalone probe while idle; both require explicit ack.
  The check command names the sending binary so login shells cannot select an older
  incompatible Agent Mail CLI.
- Message/task mutations report persistence separately from recipient delivery.
- `agent retry NAME` resets notification and verification budgets together while
  preserving pause, permissions, identity and business state. It replaces public
  `agent verify` and `runtime retry` commands.
- `status` shows a short readiness table; `status --json` returns structured detail.
  Help groups common commands by purpose.
- README and the full bundled skill cover the current setup, task/agent lifecycles,
  ownership, group isolation, recovery, delivery and repair flows.

- Discoverable skills installed through skills.sh now load the installed binary’s
  guide. Binary upgrades supply matching instructions on the next guide load;
  skills.sh continues to manage installation and loader updates.

Schema 16 adds operational delivery checks. Herdr remains optional and retains
its explicit prompt-policy opt-in. Local validation passed 94 tests, strict Clippy,
formatting and diff checks.

An isolated live Codex acceptance received the challenge in a normal notification,
ran the exact acknowledgment command, and passed status --check while connected.
The task remained open; an unauthorized worker task update was rejected. Live Claude
acceptance was not run because the local Claude CLI was unauthenticated; its bridge
and inbox paths pass the automated protocol tests.

Known Herdr limitation: the existing reminder scheduler still has a bounded
per-agent retry budget and does not reset an exhausted budget merely because new
mail arrives while older obligations remain open. Issue
[#1](https://github.com/youssef-tharwat/agent-mail/issues/1) remains open.
