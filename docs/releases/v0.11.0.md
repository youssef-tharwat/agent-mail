# Agent Mail v0.11.0

Unfinished work continues through durable task and checkpoint deadlines in the
existing service. A status reply or turn ending leaves the task pending; the
service resumes it or visibly escalates to its writer while preserving approval
holds, including after restart.

## Changes

- Remove runtime turn/offer tracking, completion replay, lifecycle subscriptions,
  and turn-receipt diagnostics. Continue through persisted deadlines and bounded
  reminders using the existing worker.
- Serialize external wakes per participant. Preserve an unconfirmed native wake's
  retry delay when fresh events arrive, and expose uncertainty across restarts.
- Route due blocked/review tasks to their decision owner without worker reminders,
  even when they have an active checkpoint or satisfied dependency.
- Wake the service at scheduled deadlines and recover missed hints through its
  bounded periodic scan.
- Add group-visible records with immutable revisions, typed artifacts with managed
  storage and verification, and audited task coordination: relationship facts,
  prerequisites, writer transfer, and paginated task history/messages.

## Upgrade

Run `brew upgrade youssef-tharwat/tap/agent-mail`, or use the published native
archive or installer. Binaries support macOS and Linux on ARM64 and x86-64.

Automatic upgrades preserve existing tasks, messages, registrations, retry
budgets, pause settings, and saved follow-through policies, with verified backups.
Schema 22 adds records, artifacts, and task coordination. Previously shipped
migration history remains intact; continuation simplification adds no migration.
The removed `turn_receipts` diagnostic fields are no longer returned in status.
New groups enable follow-through by default; existing saved policies stay intact.

## Validation and scope

Full tests, formatting, and strict Clippy passed on the merged change. Live Codex
0.159.3 acceptance verified partial progress followed by actual model continuation
without new prompts, with the service running continuously and after restart.
Approval holds stayed blocked, and a real coordinator consumed hold and
unavailable-runtime escalations. See the
[live acceptance evidence](../MINIMAL_CONTINUATION_LIVE_ACCEPTANCE.md).

Release automation repeats tests and builds all four platform binaries before
publication. Native delivery is bounded at-least-once; queue acceptance is not
execution or task completion. Cross-machine follow-up waits remain unsupported.
The proposed general execution platform in PRs #3 and #9 is superseded and is not
part of this release.
