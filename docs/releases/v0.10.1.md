# Agent Mail v0.10.1

This is the first published release of durable follow-through and automatic
upgrades. The v0.10.0 candidate was withheld after its Linux release checks found
two test-fixture races.

## Changes

- Track unfinished task/mail work through versioned checkpoints, explicit waits,
  bounded reminders, and escalation to the writer/sender and an operator route.
- Separate transport verification, source retrieval, reported progress, and
  completion in status and recovery. Preserve existing task and mail authority.
- Automatically coordinate schema upgrades, verified backups, worker handoff,
  and resumable watches using the current binary.
- Wake idle Herdr clients when optional launch metadata is absent; preserve
  explicit readiness and authorization holds.
- Include source mail in addressed attention details so the original sender can
  inspect an escalation without borrowing the recipient's identity or generating
  a false recipient read receipt.
- Correct release fixtures to wait for business notifications and consume notifier
  input, and remove a stale protocol version from diagnostics.

## Upgrade and activation

Run `brew upgrade youssef-tharwat/tap/agent-mail`, or install the release archive
for your platform. Schema 18 preserves tasks, messages, registrations, receipts,
retry budgets, and pause settings. Normal use performs migration with a verified
backup; read-only diagnostics do not migrate.

Follow-through starts in **observation mode**. Enable each intended group using
`attention configure --file policy.json`; see the
[activation and checkpoint guide](../usage.md#follow-through-after-delivery).
Event subscriptions use protocol 2; upgrade old watch clients when they receive
the explicit protocol error. Remote snapshots and cross-machine waits remain
unsupported for follow-through; ordinary relay contracts are unchanged.

Local validation passes 139 tests, including 21 follow-through cases, formatting,
and strict Clippy. See [implementation and live acceptance evidence](../FOLLOW_THROUGH_ACCEPTANCE.md)
for validation scope and limitations. Release checks run on macOS and Linux for
both ARM64 and x86-64 before publication.
