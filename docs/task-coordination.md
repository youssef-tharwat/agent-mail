# Task coordination and retained audits

Task decisions belong to the logical writer mailbox. Owner reassignment moves execution responsibility only. Session replacement for that mailbox retains its logical authority, while stale session generations fail authentication.

`task transfer-writer ID --file transfer.json` requires the current writer's session, the observed task version, expected old writer, enrolled new writer, observed new writer binding generation, and a reason. The destination must be a registered local mailbox in the same group on the home machine. Remote routed mailboxes can own execution work, but writer transfers to them are rejected because task decisions require a local authenticated home-machine identity. Identical retries return the committed result; changed retries conflict. The explicit sessionless `--operator-recovery` route uses the local state directory's operator authority and records `operator:local` in the audit. Protect access to that directory as operator credentials. Transfers preserve the task owner, approval holds, evidence, deadlines, lifecycle, and all private mail dispositions. Task follow-up escalation authority follows the new writer. Existing private reports remain in their original inbox; recipients must deliberately share them through ordinary mail or a shared record. A task link grants no access to private message bodies.

`task relate ID --file relation.json` requires the source writer and observed versions of both same-group endpoints. `parent` expresses ownership hierarchy, `related` is informational, and `dependency` expresses a prerequisite fact. Parents and dependencies each reject cycles within their own meaning; checkpoint prerequisites and explicit dependency facts share cycle checks. Removing an edge sets `active:false` and retains its audit. Cancellation and reopening retain every edge. Exact `review_round` and `source_revision` query filters distinguish old review coverage from current coverage. Linking does not grant approval or complete a task.

A checkpoint may use `waiting:{"kind":"tasks","mode":"all","tasks":[{"id":"review","states":["accepted"],"accepted_revision":"revision-a"}]}`. Use `any` for alternatives. One to thirty-two prerequisites persist in the existing scheduler. Cancellation qualifies only if explicitly selected; reopening or a changed accepted revision stops qualification. Dependency readiness produces bounded reassessment attention under the current checkpoint version. It never clears a blocked/review hold, extends the escalation deadline, or accepts work. Replace the checkpoint using its observed version when dependencies change. An informational relationship does not automatically create a checkpoint wait.

Normal context and legacy task listing remain bounded to open obligations. Opt-in task discovery includes all same-group task states, including done, accepted, and cancelled; optional owner/state filters narrow the result. All group participants may read task facts and retained decision history on the home machine. Linked-message pages contain identifiers, sender, creation time, and whether the caller has message visibility; they exclude all bodies and summaries.

History and linked-message pages default to twenty records, with an explicit maximum of one hundred. Continue with `next_cursor` until it is null. Cursors are bound to the group, logical actor, binding generation, task, and filters. History orders by descending version and linked messages by descending message ID. Their initial ceiling excludes later concurrent additions, so one traversal reaches the complete retained historical range without duplicates. Task discovery orders by ascending task ID and relationship queries by ascending edge ID; these are live traversals: concurrent inserts before the cursor require a fresh traversal, and state/link changes are visible at the time of each page. Reads do not decide work or resolve messages. Remote audit surfaces require the home machine; normal remote recovery keeps its existing snapshot behavior.

Remote task discovery includes locally received home snapshots. Remote relationship queries use home snapshots and label their live cache consistency. Complete retained history remains on the home machine; a remote history response explicitly reports `complete:false` and returns only the latest received task snapshot. A source task retains at most one thousand relationship edges, including superseded edges, and its transport snapshot is limited to 192 KiB. These bounds reject the mutation atomically rather than truncating its recovery facts.
